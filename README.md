# دوّار — Next.js Edition

إعادة بناء موقع "دوّار" (كان ملفات HTML/JS ثابتة) إلى تطبيق ويب حقيقي:

**Next.js 14 (App Router) + TypeScript + React + Prisma/SQL + NextAuth (Twitch) + Git**، مع أنيميشن قوي بـ **GSAP**.

## ✅ الأقسام الجاهزة والشغّالة بالكامل
- **تسجيل الدخول بتويتش** — حقيقي وآمن (Authorization Code flow بالسيرفر، مو implicit flow بالمتصفح زي الأصلي)
- **عجلة الشخصنة** — كاملة: دوران، طرد، إنعاش، طردة الدبل ⚡x2
- **6 ألعاب أسئلة/إجابة** (محرك واحد مشترك `src/lib/trivia/*`، بيانات منقولة حرفياً من الموقع الأصلي):
  - خلية الحروف (32 لغز) · أسرع كلمة (1258 كلمة) · تخمين الأعلام (137 دولة) · تخمين العواصم (137 دولة) · تخمين الإيموجي (700 سؤال) · الكويز (1011 سؤال)
  - الإجابات الصحيحة تتحقق **بالسيرفر بس** وما ترجع للمتصفح إطلاقاً — محد يقدر يغش من الـ DevTools
- **لعبة الذاكرة** — لوحة مشتركة، أي لاعب يقلب بطاقة عبر الـ API، نظام النجوم/الترقية (5/10/15 زوج = 1/2/4 لفل)
- **المتجر** — إطارات وبنرات حقيقية (منقولة من `profile.js` الأصلي)، شراء بالنقاط من قاعدة بيانات حقيقية
- **المتصدرين** — ترتيب حسب عدد الفوزات، منصة (podium) متحركة
- **الإعدادات** — حالة ربط تويتش، المحفظة، المقتنيات، صلاحية الأدمن

## 🚧 لسا ما انبنى (خارطة طريق بالأسفل)
الكراسي الموسيقية، صراع الفواكه، تصادم السيوف، تحدي الرسم — أربع ألعاب ببنية خاصة (مو نفس نمط سؤال/جواب) لسا ما انبنت. وصفحات المهام والشارات ولوحة الأدمن.

## 🏗️ البنية التقنية

```
dawwar-next/
├─ prisma/
│  ├─ schema.prisma      ← نموذج قاعدة البيانات (SQL عبر Prisma ORM)
│  └─ seed.ts             ← بيانات تجريبية (غرفة + 8 لاعبين)
├─ src/
│  ├─ app/
│  │  ├─ page.tsx          ← الصفحة الرئيسية (قائمة الألعاب)
│  │  ├─ roulette/page.tsx ← لعبة العجلة الكاملة
│  │  └─ api/rooms/...     ← الـ Backend (Route Handlers بـ TypeScript)
│  ├─ components/          ← Wheel, PlayerTargetGrid, JoinPanel, WinnerOverlay
│  ├─ lib/                 ← منطق اللعبة الصرف (rouletteEngine.ts) + Prisma client
│  ├─ hooks/                ← useRoomPolling (يحدّث الحالة كل 1.5 ثانية)
│  └─ types/                ← أنواع TypeScript المشتركة
├─ package.json
└─ tsconfig.json
```

### ليش هذا التقسيم؟
- **`lib/rouletteEngine.ts`**: كل قواعد اللعبة (الإنعاش، طردة الدبل ⚡x2، اختيار الدور) بدوال **صرفة pure functions** بدون أي اتصال بقاعدة البيانات — سهلة الاختبار ومنطقها واضح لوحدها.
- **`app/api/rooms/...`**: طبقة الـ Backend الحقيقية. كل الحسابات المهمة (مين دوره، مين فاز) تصير **بالسيرفر** مو بالمتصفح، عشان محد يقدر يغش من الـ DevTools.
- **قاعدة بيانات SQL حقيقية عبر Prisma**: كل غرفة، لاعب، وحدث طرد/إنعاش يتخزن بجدول SQL (`Room`, `Player`, `TurnEvent`, `Winner`) — مو بـ localStorage زي النسخة الأصلية.

## 🚀 التشغيل المحلي

```bash
npm install
npx prisma generate
npx prisma db push      # يبني ملف dev.db (SQLite) من الـ schema
npm run db:seed         # (اختياري) يحط غرفة تجريبية فيها 8 لاعبين
npm run dev
```

افتح http://localhost:3000

> **ملاحظة عن بيئة التطوير الحالية (Claude sandbox):** الشبكة هنا مقفولة على مجموعة نطاقات محددة، ومنها `binaries.prisma.sh` (اللي Prisma يحمّل منه محرك الاستعلام) غير مسموح. هذا خلى أمر `prisma generate` ما يكمّل بالكامل هنا، بس هذا قيد بيئة الحاويّة بس — على جهازك (أو أي سيرفر عادي بإنترنت طبيعي) الأمر بيشتغل عادي بدون أي تعديل بالكود. تأكدت إن الكود نفسه سليم 100%: `npx tsc --noEmit` و `next build` (مرحلة الـ compile والـ type-check) نجحوا بدون أي خطأ — الفشل الوحيد كان بتحميل ملف ثنائي خارجي مو متعلق بجودة الكود.

### التبديل لـ Postgres بالإنتاج
بدون تغيير أي موديل، بس بدّل بـ `prisma/schema.prisma`:
```prisma
datasource db {
  provider = "postgresql"   // بدل "sqlite"
  url      = env("DATABASE_URL")
}
```
وحط رابط Postgres الحقيقي بمتغير البيئة `DATABASE_URL`.

## 🎮 كيف تشتغل لعبة العجلة

1. **إنشاء غرفة** → يرجع كود قصير (5 حروف) يشاركه المضيف
2. **انضمام اللاعبين** بالكود
3. **"دوّر العجلة"**: السيرفر يختار الفايز عشوائياً *قبل* أي أنيميشن (`/api/rooms/[code]/spin`)، والمتصفح بس يرسم دوران GSAP يوصل بالضبط على النتيجة المحسومة من السيرفر — يعني ما فيه غش ممكن من طرف العميل
4. **صاحب الدور يطرد أو ينعش** لاعب من `PlayerTargetGrid` (الأسماء تبان كاملة دايماً، بدون قص — نفس الإصلاح اللي طلبته بالنسخة القديمة)
5. **طردة الدبل ⚡x2**: الفايز بالجولة السابقة ياخذها تلقائياً، وتبان كبادج ذهبي متحرك بأي مكان يبان فيه اسمه
6. **آخر لاعب ناجي = الفايز** → شاشة احتفال GSAP (قصاصات ورق + قفزة العداد) وتسجيل الفوز بجدول `Winner`

## 🗺️ خارطة الطريق لباقي الألعاب

نفس النمط بالضبط لكل لعبة:

| الخطوة | مثال |
|---|---|
| 1. أضف موديل Prisma للعبة | `MemoryRound`, `MemoryCard` |
| 2. اكتب منطق اللعبة الصرف بـ `lib/` | `memoryEngine.ts` (حساب النجوم/اللفلات) |
| 3. Route handlers بـ `app/api/games/memory/...` | `flip`, `match`, `next-round` |
| 4. صفحة `app/memory/page.tsx` + مكوّنات GSAP | بطاقات تنقلب بـ `rotateY` |
| 5. اربطها بالصفحة الرئيسية (`GAMES` array بـ `page.tsx`) | غيّر `live: false` إلى `true` |

الألعاب الجاهزة للنقل بهذا النمط: **لعبة الذاكرة، خلية الحروف، أسرع كلمة**، وبعدين الباقي.
